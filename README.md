# Viviani's theorem for simplices in Lean 4

A Lean 4 + Mathlib formalisation of **Viviani's theorem**, generalised from equilateral triangles to simplices of every positive dimension: for a point in the affine span of a simplex, the signed facet distances divided by the heights sum to 1; the distance sum is constant iff all heights are equal; regular simplices have equal heights.

**Status:** all statements proved, with no `sorry`. `gate.sh` checks 10 named declarations.

## Main statements

| Lean name | File | Statement |
|---|---|---|
| `Affine.Simplex.sum_signedInfDist_div_height` | `Basic.lean` | Σ dᵢ(p)/hᵢ = 1 for any simplex |
| `Affine.Simplex.sum_signedInfDist_eq_height` | `Heights.lean` | equal heights ⇒ Σ dᵢ(p) = h |
| `Affine.Simplex.exists_forall_sum_signedInfDist_eq_iff` | `Heights.lean` | the sum is constant iff all heights are equal |
| `Affine.Simplex.Equilateral.height_eq` | `Equilateral.lean` | equal edge lengths ⇒ equal heights |
| `Viviani.equilateral_triangle'` | `Equilateral.lean` | the classical equilateral-triangle case, unsigned distances, closed interior |

## Verification

`./gate.sh` builds the library and generates its own `#print axioms` queries for the 10 named
declarations (every Lean name cited in the accompanying paper, plus those queried during
development). The queries are generated by the gate itself, not read from a file in the repository.

The gate fails if any of the following is true:
- a source file contains `sorry`, `admit`, `native_decide`, `axiom`, `#eval`, `run_cmd`, `set_option`, `macro`/`elab`/`syntax`/`notation`, or `import Lean`;
- the build fails;
- a named declaration is missing, or has an extra report;
- a named declaration depends on anything other than `propext`, `Classical.choice` and `Quot.sound`.

Output: `PASS (10 declarations, standard axioms only)`.

`tests/tamper.sh` plants six kinds of fake proof in scratch copies and checks that the gate
rejects each one (a rejection must exit nonzero and print the expected `FAIL` message): a `sorry`; an axiom split across two lines; an `#eval` printing a fake axiom
report; a custom macro; a weakened statement (equilateral Viviani without the closed-interior hypothesis: false for points outside.); and a genuine extra
axiom with a long name, so that the report wraps over several lines.

`code/` contains independent numerical checks (Python, exact or high-precision arithmetic) of the
identities and of the hypotheses' necessity. `scratch/` contains the `#print axioms` driver files used during development; their recorded
outputs, cited in the paper, are the `*.out` files there and the log files at the repository root.

## Build

```sh
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh   # if Lean is not installed
lake exe cache get
lake build
./gate.sh
bash tests/tamper.sh
```

Toolchain: Lean `v4.33.1`, Mathlib `v4.33.1` (revision pinned in `lake-manifest.json`).

## Note on how this was produced

The formal proofs, checking scripts and documentation were developed with the help of a
large-language-model AI assistant. The author directed the work, checked the formal statements
against their informal counterparts by hand, and is responsible for the result. The Lean kernel
checks every proof.
